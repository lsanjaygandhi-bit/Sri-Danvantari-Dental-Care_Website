## Visible "Admin Login" button in the header (11 Oct 2026)
Requested: a clearly visible Admin Login button beside Contact on every page, and in the mobile menu.

**Why there was no button before:** (1) in the previous revision the header button from the uploaded fix was replaced, as agreed then, by a small footer "Staff login" link, so nothing showed in the header; (2) `js/cms.js` rebuilds the header menu from the database once Supabase is connected, so a plain link added to the menu would have disappeared on connected sites; (3) before Supabase is configured, the admin page showed only one line of text, which looked broken.

| File | Change |
|---|---|
| all 11 `*.html` pages | `<a class="nav-admin" href="admin/index.html" data-nav-fixed>Admin Login</a>` inside `<nav id="nav">`, immediately after Contact. Because it is inside the existing menu, phones show it in the ☰ menu automatically. |
| `js/cms.js` | When the CMS rebuilds the header menu, links marked `data-nav-fixed` are kept at the end, so the button cannot be removed by menu edits or by the database. |
| `styles.css` | Appended rules scoped to `.nav a.nav-admin`: a purple pill in the brand colour; on phones, a full-width button in the open menu. The header height is unchanged (83 px desktop, 71 px phone). |
| `admin/js/app.js` | Before Supabase is configured, the admin page shows a clear card, "Admin Login is not connected yet", with the setup steps and a link back to the website, instead of one line of text. Sign-in itself is unchanged: Supabase Auth plus an admin role checked by the database. |
| `tools/localstack/header-button.test.mjs` *(new)*, `run-all.sh`, `public-parity.test.mjs`, `admin-e2e.test.mjs`, `static-checks.mjs` | 37 new browser checks (5 desktop widths, all page types, phone menu, click-through and sign-in); the existing suites now expect the button. |

The footer "Staff login" link is kept as a second way in.
